# auth-service

**Owner:** TV1.

Auth Contract v1.0 persistence: accounts, role grants, refresh families/tokens and durable profile provisioning tasks. No Auth HTTP API, token issuing or provisioning worker yet.

Runtime uses `auth_app`, `ddl-auto=validate` and disabled Flyway. Provision roles/database first using [Docker instructions](../../docker/README.md). After checking the target DB inventory, activate `migration` with separate `AUTH_MIGRATION_PASSWORD`; V1 requires `auth_migrator` on `auth_db`. It grants DML only on named business tables, excluding Flyway history. Never enable baseline/clean against existing data. Roll back application code while retaining tables/data; schema corrections require a new migration.

From `backend`, use Java 21 and JVM UTC: `./gradlew :auth-service:test`. The PostgreSQL 16 Testcontainers suite requires Docker and fails if unavailable. Older Testcontainers clients against Docker 29 may need `-Dapi.version=1.44` in session `JAVA_TOOL_OPTIONS`, alongside `-Duser.timezone=UTC`.

`TV1_DATABASE_TESTS=true` additionally runs `DatabaseReadinessTest` against the configured database: its explicit migration profile now migrates pending versions using migration credentials, then validates runtime JPA and Flyway. Supply both Auth passwords; leave this opt-in unset when testing only isolated containers.

Email normalization is Java `strip().toLowerCase(Locale.ROOT)` on creation and normalized lookup, protected by database uniqueness. Account status is required without an implicit default or a new status vocabulary. Role synchronization and provisioning retry policy remain for their contract/implementation PRs.

V1's `lower(email COLLATE "C")` only checks ASCII case. [V2](src/main/resources/db/migration/V2__enforce_java21_email_canonical_form.sql) adds a Java 21 canonical-form check while retaining the existing unique key and V1 bytes. It permits canonical Unicode, including lowercase expansions, without adding ASCII-only, NFC, accent folding or case folding. The pinned Unicode character sets are verified against Java 21 and PostgreSQL 16; revisit them before changing the JDK's Unicode version. V2 rejects noncanonical stored values rather than changing account data. Inventory existing emails using Java normalization and have TV1 resolve conflicts before rollout.

V2 is now in `db/migration`; runtime Flyway remains disabled. The isolated `AuthPersistenceTest` uses this normal location to apply V1 then V2, check preserved ASCII/Unicode data and checksums, reject legacy noncanonical rows (with and without canonical duplicates) without changing them, and validate/restart. Do not enable `migration` or `TV1_DATABASE_TESTS` against an existing database during this review. TV1 must review a safe restored-backup rehearsal and the table-scan/DDL lock window before rollout. Never repair V1 checksums or clean/baseline an existing database to pass validation.

For a read-only inventory, set `AUTH_EMAIL_INVENTORY_JDBC_URL` to the reviewed Auth database and `AUTH_DB_PASSWORD` to its existing `auth_app` password, then run `:auth-service:test --tests '*EmailInventoryTest'`. This test does not start Spring or Flyway: it reads only IDs/emails in a repeatable-read, read-only transaction, uses `Account.normalizeEmail`, rolls back, and reports counts/account IDs without email values. Inventory conflicts remain for TV1 to resolve. To retain isolated test databases/volumes, set `TV1_RETAIN_TEST_DATABASE=true`, `TESTCONTAINERS_RYUK_DISABLED=true` and `TESTCONTAINERS_REUSE_ENABLE=true`; the suite prints the retained container ID for review.

For refresh mutation, start one transaction, lock the family through `lockByTokenHash` (including used hashes) or `lockById`, then inspect/consume the token and insert its child or revoke the family before commit. `consume` also acquires that family row lock itself in a materialized SQL CTE, so omitting the explicit lock cannot bypass logout/rotation serialization; `MANDATORY` prevents a standalone transaction around only consumption. The lock remains until the caller commits/rolls back. Keep the explicit lock before inspecting session state, and use it for every revoke path. `consume` is a bulk update; do not rely on a previously loaded token's `usedAt` afterward. Family revocation invalidates every descendant; hashes remain stored for reuse detection. Runtime has no token DELETE privilege; expiry cleanup needs a separately reviewed job.
