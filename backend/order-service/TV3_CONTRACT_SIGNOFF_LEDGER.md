## Inventory — Product/SKU identity, reservation lifecycle, operationId and unknown outcome

1. **Concrete provider facts:** Inventory keys by opaque global `sku`, quantity positive `long`; TV2 selected Product-owned exact immutable *global SKU uniqueness as target*, **not yet enforced in production DB/API**. `POST /api/inventory/operations` has step-specific stable `operationId` and separate `RESERVE`, `CONSUME`, `RELEASE` types. Inventory hashes type + sorted canonical SKU/quantity, replay same ID/payload without another mutation, 409 `IDEMPOTENCY_KEY_REUSED` for mismatch; DB locks and local atomic multi-SKU transaction. `productId` is not `sku`. **Order/attempt ID is a correlation ID only**, not the three operation IDs.
   - **TV3/TV4 scope-approved proposals C03/C04/C05:** Order-owned V2+ immutable exact line journal; persist committed **T1 intent/step ID before outbound HTTP**, T2 outcome after HTTP; no transaction spans network; RESERVE after Cart claim + *authoritative* Catalog and *approved* Finance checks, before Order confirmation.
   - **TV4 proposal C06 requires cross-owner revision:** CONSUME only after verified, durably committed dispatch/handoff, separate from DELIVERED/COD; RELEASE once only on proven pre-dispatch cancellation/rejection of still-reserved lines; after dispatch inspection-confirmed return uses separate INCREASE, never RELEASE consumed stock. **Conflict to resolve:** earlier TV3 draft uses `READY_FOR_HANDOFF → DISPATCHED`, while new [TV4 PR #39](https://github.com/duyxl56785/Project_HK5/pull/39) drafts `PACKING → SHIPPED` (and `PENDING_CONFIRMATION → CONFIRMED`). These are not silently interchangeable event or enum contracts.

Inventory has **no operation-status lookup by ID, reservationId, orderId line ownership API** today; GET balance is **not** an operation outcome query. Never blindly RELEASE on timeout or uncertain Order commit. Retry count, backoff, SLA/ops escalation and status query authority need joint decision.

## Security — internal caller credential, operation allowlist, delegated/current authorization

Internal routes are not public Gateway routes; **OD-09** requires distinct caller→callee opaque high-entropy credentials (NOT JWT signing keys), verified caller identity, allowlist *method+path+operation*, default deny, and separately verified delegated Bearer/current ownership for user operations. Current broad `X-Inventory-Internal-Token` has no caller-specific pair scope: **do not give it to Order/Checkout**. Current Product batch path intentionally returns fallback 403.
